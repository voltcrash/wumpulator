    How the search works

    The grid is a graph

    Every safe cell is a vertex. Two safe cells that share a side are joined by an edge, so each legal move up, right, down or left is one edge and every move costs the same. Pits and the Wumpus are not vertices at all. Each vertex keeps an adjacency list of its neighbours in the fixed order up, right, down, left, so every run is reproducible.

    Search order is not the route

    The numbers on the cells show the order in which cells were discovered. A search usually discovers many cells that never make it onto the final route. The route is rebuilt afterwards: BFS follows parent links back from the gold, and DFS reads its stack from bottom to top.

    Run a search to compare its discovery order with the route it returns.

    Cost: O(V + E) time, O(V) space

    Time. Each vertex is discovered at most once, so it enters the queue or stack at most once: O(V). Each adjacency list is scanned once, and the lists hold 2E entries in total: O(E). Together, O(V + E).

    Space. The discovered and parent arrays have one entry per vertex, and the queue or stack can never hold more than V cells, so the extra memory is O(V).

    On an n × n grid V ≤ n² and E < 2n², so both searches run in O(n²). The counts below are operations, not seconds. Changing the playback speed does not change them.
